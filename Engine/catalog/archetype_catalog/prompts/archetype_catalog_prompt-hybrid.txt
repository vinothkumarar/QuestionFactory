==================================================
1. QUESTION FACTORY HIERARCHY
==================================================

Concept
    ↓
Question Possibility
    ↓
Archetype
    ↓
Question

Concept defines knowledge.

Question Possibility defines the assessment objective.

Archetype defines HOW that Question Possibility is
assessed.

Question is the concrete instance.

Do NOT collapse these layers.

An Archetype is an assessment pattern and reasoning
pathway that can be reused to generate multiple
different questions from the SAME Question Possibility.

An Archetype is NOT:

• A Concept
• A Question Possibility
• A Topic
• A Learning Outcome
• A Property
• A Fact
• A Formula
• A Knowledge Point

==================================================
2. STRICT QUESTION POSSIBILITY BOUNDARY
==================================================

Every Archetype MUST assess the supplied Question
Possibility.

Do NOT:

• create Concept variants
• create Question Possibility variants
• introduce neighboring concepts
• introduce adjacent chapters
• introduce unrelated knowledge
• change the underlying assessment objective
• expand beyond the supplied Question Possibility

If a candidate primarily belongs to another Question
Possibility, reject it.

The supplied Question Possibility is the boundary.

==================================================
4. DISTINCTNESS AND MERGING
==================================================

The objective is:

COMPLETE DISTINCT ARCHETYPE SPACE

NOT maximum count.

NOT minimum count.

Merge two candidates only when their overall assessment
strategy and reasoning pathway are materially equivalent.

Evaluate:

• Direction of reasoning
• Information given
• Information inferred
• Decision process
• Constraint structure
• Reasoning stages
• Comparison method
• Validation method
• Deduction method
• Reverse inference
• Case analysis
• Required conclusion

Sharing the same formula, theorem, property, calculation,
or intermediate operation does NOT automatically make two
Archetypes identical.

The following MAY be distinct when academically valid:

• Forward reasoning vs reverse reasoning
• Ranking vs feasibility
• Prediction vs reconstruction
• Direct inference vs consistency validation
• Existence vs uniqueness
• Normal case vs exception case
• Single-condition vs multi-condition reasoning
• Direct determination vs constraint-based determination

Do NOT merge merely because candidates share an
intermediate operation.

Merge when a student would use essentially the same
overall assessment strategy from the supplied information
to reach the required conclusion.

IMPORTANT COVERAGE CHECK

Before merging candidates, verify whether they differ
in the TYPE OF EVIDENCE used to reach the conclusion.

The following may be distinct when independently valid:

• Structural evidence
• Numerical/equational evidence
• Periodic-trend evidence
• Electron-configuration evidence
• Stoichiometric evidence
• Charge-balance evidence
• Experimental/property evidence
• Reverse reconstruction
• Error/consistency validation

Do not merge these merely because they ultimately
support the same conclusion.

Merge only when the evidence structure and overall
assessment strategy are materially equivalent.

==================================================
4A. CORE ARCHETYPE ACCEPTANCE TESTS
==================================================

Before accepting any candidate Archetype, apply ALL
of the following tests.

TEST 1 — SAME QUESTION POSSIBILITY

Does the candidate assess exactly the supplied
Question Possibility?

If NO:
    REJECT.

TEST 2 — DISTINCT REASONING PATHWAY

Does the candidate require a materially different
reasoning or assessment pathway from the accepted
Archetypes?

If NO:
    MERGE with the equivalent Archetype.

TEST 3 — SAME ALGORITHM TEST

If two candidates can be solved using substantially
the same sequence of reasoning steps, treat them as
the SAME Archetype.

Do NOT create separate Archetypes merely because
numbers, symbols, objects, representation, or wording
change.

However, sharing a formula, property, theorem, or
intermediate operation does NOT by itself prove that
the overall assessment strategy is identical.

TEST 4 — REUSABILITY

Can the candidate generate multiple academically
distinct questions without changing the underlying
Question Possibility?

If NO:
    REJECT.

TEST 5 — JEE VALUE

Does the candidate provide meaningful assessment
value for JEE Main, JEE Advanced, or serious JEE
preparation?

If NO:
    REJECT.

TEST 6 — KNOWLEDGE BOUNDARY

Does the candidate remain completely inside the
supplied Question Possibility?

If NO:
    REJECT.

TEST 7 — REASONING DEPTH

Does the candidate involve meaningful application,
inference, deduction, comparison, validation,
constraint handling, reverse reasoning, multi-step
reasoning, or another academically meaningful
assessment mechanism?

If it is merely direct recall or recognition:
    REJECT.


==================================================
4B. FINAL MERGE DECISION
==================================================

Two candidates MUST be merged only when they are
substantially equivalent across the major dimensions
of assessment.

Consider:

• Direction of reasoning
• Information given
• Information inferred
• Decision process
• Constraint structure
• Number and type of reasoning stages
• Type of comparison
• Type of validation
• Type of deduction
• Type of reverse inference
• Type of case analysis
• Type of conclusion required
• Type of evidence used

FINAL MERGE DECISION

Before merging two candidates, ask:

"Would a student use essentially the same overall
assessment strategy from the supplied information
to reach the required conclusion?"

If YES:
    MERGE.

If NO:
    RETAIN BOTH, provided both are independently
    JEE-worthy, reusable, and remain within the same
    Question Possibility.

Do NOT merge merely because the same formula,
property, theorem, or intermediate operation appears
in both.

==================================================
5. REJECT SUPERFICIAL VARIATIONS
==================================================

The following do NOT create separate Archetypes:

• Different numerical values
• Different symbols
• Different names
• Different wording
• Different units
• Different cosmetic formatting
• Table vs text when reasoning is identical
• Graph vs text when reasoning is identical
• Diagram vs text when reasoning is identical
• Data layout changes
• Presentation-only changes

Prefer one reusable Archetype over superficial variants.


==================================================
5A. PARAMETER VARIATION RULE
==================================================

Changing parameters does NOT automatically create a
new Archetype.

The following are normally NOT separate Archetypes:

• Different numerical values
• Different coefficients
• Different constants
• Different variables
• Different labels
• Different element names
• Different atomic numbers
• Different charge values

Create a separate Archetype only when the parameter
introduces a materially different reasoning mechanism,
such as:

• Constraint analysis
• Case splitting
• Feasibility analysis
• Optimization where applicable
• Boundary analysis
• Existence / non-existence reasoning
• Uniqueness / multiplicity reasoning
• Reverse inference
• A materially different decision process

The parameter itself is not the Archetype. The changed
reasoning mechanism is.

10A. FINAL QUALITY CONTROL
==================================================

Before returning the final catalog, perform an internal
review of EVERY candidate Archetype.

For each candidate, verify:

1. Is it inside the supplied Question Possibility?
2. Is it JEE-worthy?
3. Is it reusable?
4. Does it require meaningful reasoning?
5. Is it materially different from every other
   accepted Archetype?
6. Is it merely a presentation variation?
7. Is it merely a numerical or parameter variation?
8. Is it merely recall or recognition?
9. Does it duplicate another reasoning pathway?
10. Does it introduce a different knowledge point or
    Question Possibility?

Reject any candidate that fails a mandatory test.

After this review, perform a final pairwise comparison
of all remaining Archetypes.

If two are substantially equivalent:
    KEEP ONE.

If they are materially different and both are
independently JEE-worthy, reusable, and within the
same Question Possibility:
    KEEP BOTH.

The final review must prevent BOTH:

• OVER-GENERATION
• UNDER-DISCOVERY
