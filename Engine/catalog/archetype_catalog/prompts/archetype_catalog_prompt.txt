ARCHETYPE DEFINITION
--------------------------------------------------

AR-01 QUESTION FACTORY HIERARCHY

Concept
    → defines knowledge

Question Possibility
    → defines assessment objective

Archetype
    → defines assessment pattern

Question
    → defines concrete instance

Do NOT collapse these layers.

--------------------------------------------------

AR-02 WHAT AN ARCHETYPE IS

An Archetype IS:

• An assessment pattern
• A reasoning pattern
• An information presentation pattern
• A question construction pattern

An Archetype describes HOW a
Question Possibility is assessed.

--------------------------------------------------

AR-03 WHAT AN ARCHETYPE IS NOT

An Archetype is NOT:

• A Concept
• A Question Possibility
• A Topic
• A Learning Outcome
• A Property
• A Fact
• A Formula
• A Knowledge Point

Do NOT generate additional
knowledge points.

Do NOT generate Concept variants.

Do NOT generate Question
Possibility variants.

--------------------------------------------------

GOOD EXAMPLE

Question Possibility:

Determine ionic charge after
electron transfer.

Valid Archetypes:

• Electron configuration analysis
• Periodic table position analysis
• Lewis diagram interpretation
• Ionic formula completion
• Tabular data interpretation
• Assertion–Reason evaluation

All assess the SAME Question
Possibility.

--------------------------------------------------

BAD EXAMPLE

Question Possibility:

Determine ionic charge after
electron transfer.

Invalid Archetypes:

• Electrostatic attraction
• Octet attainment
• Ionic conductivity
• Lattice energy
• Solubility

These are Concepts,
Knowledge Points,
or Question Possibilities.

They are NOT Archetypes.

DISCOVERY RULES
--------------------------------------------------

1. Discover ALL Archetypes.

2. Include:

   • Foundation archetypes
   • Standard archetypes
   • Advanced archetypes
   • JEE Main archetypes
   • JEE Advanced archetypes
   • Analytical archetypes
   • Data interpretation archetypes
   • Assertion–Reason archetypes
   • Comparative archetypes
   • Multi-step reasoning archetypes

3. Do NOT generate questions.

4. Do NOT create duplicates.

5. Exhaustively enumerate the
   assessment-pattern space.

6. Generate Archetypes ONLY for the
   supplied Question Possibility.

7. Do NOT expand into neighboring
   concepts, adjacent chapters,
   broader topic areas, or additional
   knowledge points.

8. Every Archetype must represent a
   distinct assessment pattern for the
   supplied Question Possibility.

9. Different Archetypes may vary by:

   • Representation
   • Reasoning pathway
   • Information format
   • Data presentation
   • Interpretation method

10. Different Archetypes must NOT
    vary by changing the knowledge
    being assessed.

11. All Archetypes generated for a
    Question Possibility must assess
    the SAME Question Possibility.

12. Only the assessment pattern may
    change.

13. The underlying Question
    Possibility must remain unchanged.

13A. If two Archetypes assess the
same Question Possibility using the
same assessment pattern, keep only
the most general Archetype and
discard duplicates.

14. If an Archetype primarily belongs
    to another Question Possibility,
    do NOT include it.

15. Exhaust the COMPLETE assessment
    pattern space of the supplied
    Question Possibility while
    remaining strictly inside the
    Question Possibility boundary.

16. Archetypes must be reusable
question-generation templates.

An Archetype should be capable of
producing multiple distinct questions.

If an Archetype can generate only a
single question or a very narrow
variation, it is too specific and
must not be included.
